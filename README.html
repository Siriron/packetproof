Concept & Motivation

The Supply-Chain Integrity Problem

The npm and PyPI ecosystems ship billions of package installs per month. A maintainer who publishes a release with a misleading changelog — or whose release bytes differ from the committed source — can introduce vulnerabilities with no on-chain record of the discrepancy. No existing protocol locks a cryptographic pre-commitment to a release intent before publication, then independently verifies the published artifact against that commitment using multiple validators who cannot collude.

PacketProof fills that gap. Before publishing, the maintainer locks four fields on-chain: package name, registry ecosystem, version, and source commit SHA. After publication, the contract independently derives the registry URL from those locked identifiers (the caller never supplies a URL), fetches the live registry record across multiple GenLayer validators, verifies the dist-hash commitment, and uses consensus to judge whether the changelog honestly describes the changes in the commit diff. The result is a permanent, tamper-evident attestation record any downstream tool can read.

"A supply-chain attacker who controls the registry response on one validator cannot control it on all validators simultaneously."

Why Multi-Validator Consensus

The Adversarial Case

Single-party fetch cannot prove integrity. A maintainer who controls both the package registry and a single-validator chain can craft a response that makes any release look clean. GenLayer's optimistic execution model runs the same leader function on multiple independent validators, each fetching the registry live. For a CERTIFIED outcome to be issued:

  • Every validator must independently fetch the same registry record
  • Every validator must independently fetch the same commit diff
  • The payload hash must match across validators (enforced by validator_fn)
  • The deterministic verdict must be VERIFIED on all fields
  • The certification proof must re-verify the attestation digest on-chain

The challenge window adds a second adversarial layer: any non-owner address can submit evidence during the review period. If the evidence is judged relevant by consensus, a fresh independent attestation is triggered.

Intelligent Contract

Evidence Binding (Rules 0.7 + 0.8)

Deterministic URL Derivation

The caller never supplies a fetch URL. Every fetch target is derived deterministically from the locked on-chain identifiers. This is Rule 0.7 from the GenLayer Agent Playbook: a caller who supplies their own URL can point the contract at an attacker-controlled mirror. 

# npm registry — locked package_name + version only
_registry_url("npm", "mylib", "1.2.3")
# → https://registry.npmjs.org/mylib/1.2.3

# pypi registry
_registry_url("pypi", "requests", "2.31.0")
# → https://pypi.org/pypi/requests/2.31.0/json

# commit diff — locked repository_url + commit_sha
_commit_urls("https://github.com/myorg/mylib", "abc123...")
# → (.../commit/abc123....diff, .../commit/abc123...)  # Bug 9 fix

Rule 0.8 (echo check): after fetching the registry record, the contract verifies the record refers back to the locked identifiers before it influences the verdict. A MITM that returns a different package's metadata is rejected.

Four Nondet Call Sites

leader_fn
  • Fetches live registry endpoint
  • Performs Rule 0.8 echo check
  • Fetches commit diff (raw + fallback)
  • Calls exec_prompt for semantic judgment
  • Returns full payload dict with all decision fields
validator_fn
  • Checks isinstance(leaders_res, gl.vm.Return) first
  • Reads .calldata — never json.loads
  • Re-runs leader_fn() independently
  • Uses _payload_matches on all non-explanation fields
  • Validates leader_explanations shape separately

Lifecycle Flow

  1. 1

    register_package()

    Lock release intent on-chain. Validates semver, hex SHA, repo URL prefix, review window bounds. Returns pkg_key. State: DRAFT.

  2. 2

    submit_snapshot()

    After publication, owner submits a post-capture snapshot. Contract independently authenticates it against the live registry via nondet consensus. State: COMMIT_LOCKED.

  3. 3

    attest_release()

    Run full semantic attestation. Fetches registry + commit diff across validators; derives verdict deterministically. Up to 3 ordinary retries, 5 total. State: VERIFIED / INCONCLUSIVE / BLOCKED.

  4. 4

    open_challenge() — non-owner only

    During the review window, any non-owner may submit evidence. Evidence URL is independently fetched and judged for relevance by consensus. Up to 3 challenges per generation. State: CHALLENGED.

  5. 5

    reassess_challenge()

    Run a fresh attestation with the challenge context bound into the payload. Resolves the challenge and updates the package state.

  6. 6

    certify()

    After the review window closes and all challenges are resolved, owner calls certify(). The contract re-derives and verifies the attestation digest on-chain before issuing the certification_digest. Terminal state: CERTIFIED.

Audit & Bug Fixes

The contract was audited in full against the GenLayer Agent Playbook (Oct 2026), covering all 16 knowledge documents including the confirmed genlayer-test cheatcodes, the official-source deltas, portal results, and the status_code bug catalogue. Four bugs were found and fixed in the first audit; a second audit found and fixed seven more (E1–E7).

Bug A — Fixed
Module-level gl.nondet.* calls
_fetch_json and _fetch_text were defined at module level containing gl.nondet.web.get(). The genvm-linter (E010) rejects any module-level helper with nondet calls. Fixed: both helpers are now nested closures inside every leader_fn that needs them. Module level contains zero gl.nondet.* calls.
Bug B — Fixed
run_nondet_unsafe called from plain instance method
_verify_challenge_evidence was a plain instance method that called gl.vm.run_nondet_unsafe() via self.. Per Playbook §4 Bug 6: the method containing run_nondet_unsafe must be the @gl.public.write body itself. Fixed: inlined entirely into open_challenge. The leader_fn/validator_fn closures now have zero self. references.
Bug C — Fixed
Dead ternary branch in generation assignment
In _run_attestation, a ternary expression on line 660 was immediately overwritten by the following if kind == "ORDINARY" block, making the ternary unreachable dead code. Fixed: replaced with a single clean if/else branch.
Bug D — Fixed
Views returned raw dict / list — GenVM schema error
All 10 view methods were annotated -> dict or -> list and returned those types directly. Per Playbook Tier 1 rule: all views must return str via json.dumps(). The GenVM schema layer rejects a non-string view return before any logic runs. Fixed: every view now returns _dumps(...) and is annotated -> str.
Bug E1 — Fixed
copy_to_memory on plain dicts
gl.storage.copy_to_memory() was called on dicts parsed from JSON strings; the SDK asserts on non-storage values, so submit_snapshot, attest_release and open_challenge reverted. Now detached JSON copies.
Bug E2 — Fixed
Timestamp source
datetime.now() replaced by an integer-only parser of gl.message_raw["datetime"].
Bug E3 — Fixed
Ordinary-retry limit never fired
Each ordinary attempt opened a fresh generation whose count was 0. The limit is now counted per package version.
Bug E4 — Fixed
list_packages lost old packages
It was rebuilt from a 300-slot event ring. Now backed by a real package_index.
Bug E5 — Fixed
Non-object registry JSON
A valid-JSON-but-not-object reply crashed leader_fn so consensus could never settle. Now treated as unavailable.
Bug E6 — Fixed
Dist-hash format mismatch
Only key:value matched while the UI says to paste the bare registry value. Both forms match now.
Bug E7 — Fixed
In-place mutation
The consensus result is copied before fields are added.

Direct-Mode Tests

Test Suite Coverage

Tests use genlayer-test==0.29.2 from PyPI (confirmed working with the pinned runner). They run in direct mode — every nondet call is mocked via direct_vm.mock_llm(). The suite covers every reachable verdict, all guard conditions, validator re-derivation, and the full lifecycle.

Direct mode does not prove real-LLM behaviour or multi-node consensus timing. It verifies deterministic paths, guard checks, state transitions, and validator re-derivation logic.

Quick-Start

# Clone
git clone https://github.com/Siriron/packetproof
cd packetproof

# Install frontend deps
npm install

# Start dev server
npm run dev
# → http://localhost:5173

# Run contract tests (executes the real contract in direct mode)
pip install -r requirements-dev.txt
pytest

Deploy

1. Deploy the Contract

  1. Open studio.genlayer.com
  2. Create a new project, paste the contents of contracts/packet_proof.py
  3. Click Deploy — no constructor arguments needed
  4. Copy the deployed contract address from the StudioNet explorer
  5. Update src/config/chains.ts → CONTRACT_ADDRESS

2. Deploy the Frontend

# Build
npm run build

# Vercel: import the repo (framework: Vite). Netlify: drag the dist/ folder.
# vercel.json SPA rewrite is already configured
